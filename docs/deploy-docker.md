# Провижн: три способа запуска

`mkpk-provision` — один и тот же код в трёх обличьях. Выбор зависит от того,
сколько администраторов и откуда работают.

| Способ | Когда | Аутентификация |
| -------- | ------- | ---------------- |
| **Локально, CLI + `serve`** | Один админ, конфиг на его машине | Не нужна: loopback + per-session токен |
| **Десктоп** (`mkpk-provision-desktop`) | То же, но окном вместо браузера | Не нужна: то же самое в webview |
| **Общая инсталляция в Docker** | Несколько админов, один конфиг | Общий пароль, сессии, HTTPS на прокси |

Первые два — исходный сценарий, ничего не изменилось: `mkpk-provision serve --config mkpk.yaml`
слушает `127.0.0.1:8765`, конфиг не покидает машину. Ниже — третий.

## Зачем общая инсталляция

Пока у каждого админа своя копия `mkpk.yaml`, копии расходятся: двое правят одно и
то же, деплоят по очереди и затирают друг друга. Общий инстанс убирает проблему в
корне — конфиг один, передавать между админами нечего.

Цена зафиксирована в [threat-model.md](threat-model.md) и её нужно знать до
установки: в конфиге лежат SSH-креды ко **всем** роутерам, токены уведомлений и
PSK всех юзеров, а пароль — **один общий, без учётных записей**. Значит: нет
аудита по людям, нет ролей, отозвать доступ у одного админа можно только сменив
пароль всем. Для маленькой команды это осознанный размен; если он не подходит —
оставайтесь на локальном режиме.

## Вариант A: за уже существующим ингрессом

Если у вас уже есть обратный прокси (nginx/traefik/ingress), поднимаем только
контейнер и отдаём его прокси:

```sh
cd deploy/docker
cp .env.example .env        # задайте MKPK_ADMIN_PASSWORD
docker compose up -d
```

Дальше публикуете `https://mkpk.example.com` → `mkpk_provision_host:8765` своим
обычным способом. Контейнер слушает HTTP и рассчитывает, что TLS завершается
на прокси (`MKPK_BEHIND_PROXY=1` в compose уже стоит).

По умолчанию порт проброшен на `127.0.0.1:8765` — то есть доступен только с
самого хоста. Если прокси живёт на другой машине, поменяйте `ports:` на адрес,
видимый прокси, и **ограничьте доступ** сетью, а не 0.0.0.0.

## Вариант B: всё из коробки, вместе с TLS

Если прокси нет, а есть домен, смотрящий на этот хост, и открытые 80/443:

```sh
cd deploy/docker
cp .env.example .env        # MKPK_DOMAIN, MKPK_ADMIN_PASSWORD, MKPK_ACME_EMAIL
docker compose -f compose.caddy.yaml up -d
```

Caddy сам получит и будет продлевать сертификат Let's Encrypt для `MKPK_DOMAIN`
и проксирует на контейнер. Провижн при этом наружу не публикуется — только через
Caddy.

Админка с SSH-доступом ко всем роутерам в открытом интернете — плохая идея.
В `Caddyfile` заготовлен закомментированный блок `remote_ip`: раскомментируйте
и перечислите свои сети/адреса.

## Первый запуск и пароль

- `MKPK_ADMIN_PASSWORD` используется **только один раз** — при первом старте он
  хешируется (argon2id) в `/data/mkpk-admin.json`. Дальше меняется в UI
  (замок в левом нижнем углу) и **существующий файл всегда важнее переменной**:
  забытая в compose переменная не сбросит пароль.
- Сменить пароль без UI:
  `docker compose run --rm provision passwd --config /data/mkpk.yaml`
- Смена пароля завершает все остальные сессии.
- Без пароля контейнер не стартует и говорит об этом прямым текстом — это
  сделано намеренно, чтобы админка не оказалась открытой по невнимательности.

## Данные и бэкап

Всё состояние — в томе `/data`:

- `mkpk.yaml` — конфиг: роутеры, сервисы, юзеры, PSK, SSH-креды, токены;
- `mkpk-admin.json` — argon2id-хеш пароля админки (0600);
- `ssh/id_ed25519` — ключ инсталляции для деплоя (0600) и его `.pub`.

Бэкап = снимок тома. Он содержит все секреты инфраструктуры, храните
соответственно. Сессии живут в памяти процесса: перезапуск контейнера разлогинит
всех, это нормально.

## Деплой на роутеры: ключ инсталляции

`mkpk-provision deploy` ходит по SSH из контейнера, значит нужен ключ. Не берите
чей-то личный: у инсталляции есть свой — она умеет его сгенерировать.

1. В UI: иконка ключа в левом нижнем углу → **Создать ключ**. Приватная часть
   остаётся в `/data/ssh/id_ed25519` (0600) и наружу не отдаётся никогда —
   API возвращает только публичную. Из того же окна публичную часть можно
   скопировать или скачать `.pub`.
   Без UI: `docker compose exec provision mkpk-provision sshkey create --config /data/mkpk.yaml`
2. Импортируйте публичную часть на каждый роутер:

   ```routeros
   # залейте mkpk-provision.pub на роутер (Files), затем:
   /user ssh-keys import user=admin public-key-file=mkpk-provision.pub
   ```

3. В карточке роутера, в блоке SSH, нажмите **Ключ инсталляции** — путь
   подставится сам (или впишите `/data/ssh/id_ed25519` руками).

Проверить связность: `docker compose exec provision mkpk-provision deploy status --config /data/mkpk.yaml`.

Почему так лучше: ключ принадлежит инсталляции, а не человеку — уход админа не
ломает деплой, а отозвать доступ можно, удалив один ключ на роутерах.
Пересоздание ключа в UI помечено как опасное: старый перестанет подходить всюду,
куда уже импортирован.

Личный ключ тоже можно смонтировать, если он у вас уже раскидан по роутерам:

```yaml
volumes:
  - ./ssh:/data/ssh:ro
```

## Одновременная работа двух админов

Внутри общего инстанса правки не теряются: конфиг отдаётся с версией, и
сохранение поверх изменённого кем-то ещё конфига получает 409 — страница
перезагружается, правку нужно повторить. Это не блокировки и не мердж:
инструмент не даёт **потерять** чужую работу, но и не сливает две правки в одну.

## Обновление

```sh
docker compose pull && docker compose up -d
```

Образ публикуется на каждый тег: `registry.gitlab.eg23.ru/lazygatto/mikrotik-psk-knock/provision:vX.Y.Z`
и `:latest`. В проде лучше пинить версию (`MKPK_IMAGE` в `.env`), а не жить на
`latest`.

## Переменные окружения

| Переменная | По умолчанию | Смысл |
| ------------ | -------------- | ------- |
| `MKPK_ADMIN_PASSWORD` | — | Первичный пароль, только при первом старте |
| `MKPK_CONFIG` | `/data/mkpk.yaml` | Путь к конфигу внутри контейнера |
| `MKPK_ADDR` | `0.0.0.0:8765` | Адрес прослушивания внутри контейнера |
| `MKPK_BEHIND_PROXY` | `1` | Подтверждение, что TLS терминируется впереди |
| `MKPK_IMAGE` | registry-путь | Чем пинить версию образа в compose |
