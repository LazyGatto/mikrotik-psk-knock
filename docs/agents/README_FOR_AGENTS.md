# README для AI-агентов: mikrotik-psk-knock

Точка входа для любого агента, работающего с этим репозиторием. Отвечает на два
вопроса: *кто ты* и *что читать первым*. Продуктовые правила он не пересказывает —
они живут в [`AGENTS.md`](../../AGENTS.md), который остаётся единственным
источником инвариантов.

## 1. Что это за проект

Слой **PSK-time port-knock** для MikroTik RouterOS: knock с токеном,
производным от PSK и временного бакета, перед firewall-правилами роутера, плюс
инструменты провижининга и клиенты.

Это не VPN, не замена firewall'у и не универсальный «port knocker». Компромиссный
термин, пока настоящего HMAC нет:

```text
PSK time-token gated port opening for RouterOS
```

## 5. Запрещённые допущения

- Не считать, что клиент может ходить по SSH. SSH — только канал провижининга
  (`mkpk-provision deploy`), никогда не рантайм открытия доступа.
- Не менять формулу токена «по ходу дела». `sha512(psk|v1|service|client_id|bucket|psk)`
  обязан оставаться **побайтово одинаковым** в Go, Swift и в сгенерированных
  RouterOS-правилах. Золотые векторы генерируются из Go-эталона и руками не правятся.
- Не включать и не выключать NAT-правила динамически; статический `dst-nat`
  плюс `src-address-list`. Любой allow — с timeout.
- Не гадать про семантику RouterOS. Новое поведение сначала проверяется на живом
  CHR (доступ есть только у maintainer'а), потом попадает в код.
- Не добавлять стороннюю зависимость без явного обоснования и согласия
  maintainer'а.
- Не хардкодить пользовательские строки в macOS-клиенте: обе локали идут через
  `L("English text", "Русский текст")` (`Sources/MkpkApp/L10n.swift`).
- Не коммитить реальные инфраструктурные идентификаторы: хосты роутеров,
  логины, PSK, `.mkpk`-инвайты. Репозиторий публичный и зеркалится на GitHub —
  в публичных файлах не должно быть и адреса самого GitLab.
- Не считать чат или локальную файловую систему системой управления задачами.
  Это GitLab issues.
- Не заявлять «готово» без прогона, у которого прочитан **код возврата**.
  См. [`verification`](../../.agents/skills/verification/SKILL.md).

## 6. Гейт — одна команда

```bash
bash scripts/verify.sh          # go vet/build/test + swift build + mkpk-selfcheck
bash scripts/verify.sh --strict # дополнительно падает, если стадия была пропущена
bash scripts/verify.sh --docs   # плюс markdownlint по агентским документам
echo $?                         # вот это и есть гейт, а не хвост вывода
```

`swift`-стадии выполняются только на macOS; на Linux/CI они честно
докладываются как SKIP. **SKIP — не PASS**: когда пропуск недопустим,
используйте `--strict`.

Живой knock против настоящего роутера (`swift run mkpk-selfcheck live <invite> <service>`,
`mkpk knock`) в гейт не входит: он требует сети, роутера и реального инвайта с PSK.
Это ручная проверка maintainer'а.
