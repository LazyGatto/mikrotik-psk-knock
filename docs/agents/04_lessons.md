# Дневник уроков (память роя)

Одна строка на урок: **симптом → причина → лекарство**. Пишет исполнитель перед
сдачей (всякий раз, когда наткнулся на проблему среды, сборки или инструментов и
починил её) либо Team Lead на гейте. Team Lead подаёт нужные строки в бриф —
см. [`03_orchestration.md`](03_orchestration.md). Внутри раздела новые сверху.

Чего здесь нет: продуктовых решений (GitLab issues), архитектуры
(`docs/design.md`, `docs/context.md`) и структуры кода (`AGENTS.md`).

Строки с пометкой *(перенесено)* пришли из соседнего проекта maintainer'а и
описывают эту машину и эти инструменты, а не что-то наблюдённое здесь. Они всё
равно обязательны; удалять такую строку можно только после того, как она здесь
опровергнута.

## Протокол и RouterOS

- Семантика RouterOS-скриптов неочевидна (`:return` в цепочках, массивы из
  одного элемента, ключи `:serialize`, scp против sftp) → новое поведение
  сначала разведывается на живом CHR, и только потом попадает в
  `routeros/render.go`. Гадание здесь стоит дороже разведки.
- В RouterOS два разных рантайма — firewall packet path и scheduler/scripting →
  не считайте их одной атомарной программой; всё, что «сработало сразу»,
  проверяйте на задержке поллера.
- Токен `sha512(psk|v1|service|client_id|bucket|psk)` обязан быть побайтово
  одинаков в Go, Swift и в сгенерированных правилах → золотые векторы
  Swift-клиента генерируются из Go-эталона (`client/internal/token`) и никогда
  не правятся руками. Правка ожидаемого значения «чтобы тест позеленел» — это
  молчаливая поломка совместимости.
- UDP-knock не подтверждает доставку → «клиент отправил» и «роутер принял» —
  разные утверждения. Диагностика клиента формулируется в терминах проверки
  порта, а не в терминах успешности knock'а.
- Проверка порта из-под VPN/прокси-туннеля ничего не доказывает: соединение
  устанавливает туннель, а не роутер → такой результат помечается как
  «непроверено», а не как «открыто» (см. коммит `0d8354d`).

## Инструментарий и среда

- `swift test` требует **полного Xcode**; одни Command Line Tools не несут
  тестового рантайма (`lib_TestingInterop.dylib` отсутствует) → корректность
  Swift-рантайма живёт в `swift run mkpk-selfcheck`, и регрессия на найденный
  баг добавляется туда же.
- В свежем worktree нет `client-macos/.build/` → первый `swift build` — полная
  холодная сборка. Считайте в минутах, не читайте задержку как зависание.
- `~/Library/Caches/org.swift.swiftpm` и `$GOPATH/pkg/mod` общие для всех
  worktree → два одновременных первых резолва могут застопорить друг друга.
  Первую сборку каждого worktree запускайте последовательно.
- Пакет `client/cmd/mkpk-provision-desktop` (Wails) не собирается в CI: ему нужен
  платформенный webview (cgo/webkit) → он исключён из списка пакетов и в CI, и в
  `scripts/verify.sh`; собирается на macOS через `cd client && make desktop`.
- *(перенесено)* `opencode` отказывается от доступа к `/tmp` и будет его просить
  → откажите, временные файлы пишите в `tmp/` внутри worktree. Повторяйте это в
  каждом брифе; исполнители спрашивают снова.
- *(перенесено)* В zsh переменная цикла `path` **это** `$PATH` — цикл
  `while read … path` заставляет все команды исчезнуть («command not found»).
  Никогда не называйте переменную оболочки `path`.
- *(перенесено)* zsh с `noclobber`: `cmd > file` молча ничего не делает, если
  файл существует → в оркестрационных скриптах пишите `>|`.
- *(перенесено)* Вызов Bash-инструмента у Team Lead'а живёт ≤ 10 минут →
  длинные ожидания (`herdr agent wait`, `pane wait-output`) запускайте в фоне,
  а не в переднем плане.
- *(перенесено)* Команда, читающая stdin (`go run -`, `swift -` и подобные),
  вешает Bash-инструмент до таймаута → напишите временный файл и запустите его.

## Гейты и приёмка

- Гейт — это **код возврата**, никогда не grep по выводу. Шаблон:
  `bash scripts/verify.sh; echo GATE=$?`. Строка «тесты прошли» — утверждение,
  а не доказательство.
- `scripts/verify.sh` докладывает **SKIP** для стадии, которую невозможно
  выполнить на этой машине (swift-стадии не на macOS, `--docs` без npx). SKIP —
  не PASS: когда пропуск недопустим, запускайте с `--strict`.
- *(перенесено)* Числа, названные исполнителем («79 кодов», «12 файлов»),
  пересчитывайте из кода. Большинство он называет верно — именно поэтому одно
  неверное обходится дорого.
- *(перенесено)* Скрытый тест приёмки, переиспользующий общие имена хелперов,
  конфликтует с тестами исполнителя (переопределение) и даёт ложные 0/N →
  префиксуйте скрытые хелперы (`hidden*`) и всегда прогоняйте скрытый тест
  сперва против заведомо исправного эталона.

## Herdr и исполнители

- *(перенесено)* `herdr worktree create` **без `--workspace`** берёт репозиторий
  того workspace, на котором сейчас фокус у maintainer'а — worktree молча
  уезжает в другой проект, и исполнитель минутами ищет код в чужом репозитории.
  Всегда передавайте `--workspace` и сверяйте путь в JSON-ответе. То же
  относится к `pane split --current`: предпочитайте явный `--pane`.
- *(перенесено)* `herdr agent start` сразу после `tab create` / `pane split`
  возвращает `agent_pane_busy` — оболочка ещё не дошла до приглашения →
  сначала `sleep 3`.
- *(перенесено)* Многострочный `herdr agent prompt` TUI `opencode` не отправляет
  никогда (поле остаётся пустым, агент остаётся `idle`) → только однострочные
  промпты; настоящий бриф — в issue или в файле.
- *(перенесено)* `herdr agent prompt` может вернуть `idle` без ошибки и ничего
  не отправив → проверяйте `agent_status=working` через 5 с; запасной путь —
  `pane send-text` + `pane send-keys <id> enter`.
- *(перенесено)* Промпт, отправленный до готовности TUI/MCP агента, теряется →
  дождитесь шапки агента в `agent read`, затем промпт, затем подтвердите
  `working` через 10 с.
- *(перенесено)* Пустой или битый файл роли `opencode` заставляет его свалиться
  на последнюю использованную модель, без ошибки → проверяйте шапку TUI после
  `agent start`. Heredoc в zsh с `${var^}` падает с «bad substitution» и
  оставляет файл пустым; пишите файлы ролей через Write/python и проверяйте `wc -c`.
- *(перенесено)* `opencode --continue` возобновляет **последнюю сессию глобально**,
  а не последнюю для этого каталога → агент в новом worktree подхватывает чужой
  cwd и модель. Перезапускайте роль только чистым
  `agent start … -- --agent <role>`, контекст передавайте файлом.
- *(перенесено)* В TUI `opencode` клавиша `tab` переключает **роль агента** —
  никогда не посылайте её в ответ на диалог. По диалогам разрешений ходят
  стрелками.
- *(перенесено)* `codex` в свежем worktree открывает два диалога доверия и
  **съедает первый промпт** → дождитесь вопроса (`agent wait --until blocked`),
  ответьте, и только потом шлите настоящий промпт. Он также просит подтвердить
  запуск команд; следите за «Yes, proceed», когда он уходит в `blocked`.
- *(перенесено)* `codex` с истёкшим OAuth принимает промпт и умирает с 401 →
  перелогинить может только maintainer. `exit` в панели закрывает панель
  целиком; замену запускайте в новом `pane split`.
- *(перенесено)* `herdr agent start --kind codex` может молча не стартовать
  (таймаут запуска), после чего `pane send-text` уходит в оболочку — а апостроф
  в тексте («devil's») вешает zsh на `quote>`. Сначала проверьте приглашение
  агента через `pane read`, и держите текст промпта без одинарных кавычек.
- *(перенесено)* На больших задачах кодовый исполнитель **молча заканчивает ход**
  на середине, и так несколько раз. «Continue» работает, но дорого → держите
  бриф в пределах ~15 файлов либо кладите в него явный чеклист плюс «не
  заканчивай ход, пока критерии готовности не выполнены».

## Git, MR и релиз

- SSH на GitLab (порт 22) не работает → пушим по HTTPS через credential-helper
  `glab`. Ветка `main` защищена; пуш тега — отдельное действие от пуша в `main`.
- Публичное зеркало на GitHub синхронизируется вручную (`git push github main`),
  ассеты релизов — тоже (`glab release download` → `gh release …`). В
  публичных файлах (README, man) ссылки ведут на GitHub, никогда на GitLab-хост.
- Пуш, не несущий **нового коммита**, создаёт MR как **Draft**, и
  merge-when-pipeline-succeeds не срабатывает → после настоящего пуша
  `glab mr update <n> --ready`.
- *(перенесено)* Цепочка `cmd && … ; git checkout main` после упавшего
  pre-commit хука оставляет вас на `main`, и следующий коммит приземляется туда
  → проверяйте `git branch --show-current` после каждого коммита в скрипте
  приземления. Локальный `main` держите на `reset --hard origin/main`.
- *(перенесено)* Перед финальным `push -f` ветки, которая полежала, делайте
  rebase на **свежевыкачанный** `origin/main`, а не на тот `main`, что был у вас
  в начале — именно на приземлившихся тем временем правках упадёт CI. И не
  удаляйте worktree по коду возврата цикла ожидания; проверьте, что состояние MR
  действительно `merged`.

## Подпись, нотаризация, упаковка (macOS)

- Entitlement `keychain-access-groups` без встроенного в `.app` provisioning
  profile приводит к тому, что amfi убивает приложение (ошибка 163, «Launchd job
  spawn failed») → `sign.sh` применяет entitlement только при наличии
  `MKPK_PROVISION_PROFILE` (или `script/mkpk.provisionprofile`); иначе подписывает
  без него, а синхронизация через iCloud Keychain откатывается на файловое
  хранилище.
- Ресурсный бандл рядом с `Contents/` делает приложение неподписываемым
  («unsealed contents in the bundle root») → брендовые PNG укладываются прямо в
  `Contents/Resources` и грузятся через `Bundle.main`; `Bundle.module` остаётся
  только запасным путём под `#if DEBUG` (для `swift run`).
- Нотаризация требует одноразового keychain-профиля `mkpk-notary`
  (`xcrun notarytool store-credentials`) → без него `notarize.sh` не поедет, и
  завести его может только maintainer.
- Нотаризовать нужно и `.app`, и `.dmg`, со степлингом обоих → иначе первый
  запуск без сети упрётся в карантинный диалог.
