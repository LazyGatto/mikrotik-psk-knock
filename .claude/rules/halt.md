# Протокол HALT

HALT — обязательная остановка в любой ситуации, где продолжение без фиксации
проблемы ведёт к ошибке, скрытому риску или решению, принятому случайно.

Поднять HALT может любая роль — исполнитель, DA-ревьюер, Team Lead. Поднять его
никогда не считается провалом; провал — обнаружить постфактум, что кто-то должен
был это сделать.

## Триггеры

| Код | Триггер | Типичный вид в этом проекте |
| ----- | --------- | ----------------------------- |
| H-1 | Архитектурное отклонение | Задачу не сделать, не заставив клиент ходить по SSH, не включая/выключая NAT-правила динамически, не выдав allow без timeout |
| H-2 | Нет данных | Неизвестно, как ведёт себя RouterOS в нужном случае, и проверить это можно только на живом CHR — доступ есть у maintainer'а |
| H-3 | Каскадный эффект | Изменение тянет за собой формат `.mkpk`-инвайта, формулу токена или сгенерированные `.rsc` — то есть ломает уже розданные инвайты либо уже задеплоенные роутеры |
| H-4 | Риск безопасности | PSK может попасть в лог, argv, crash-репорт или отслеживаемый файл; в репозиторий просится реальный хост/логин/инвайт; проверка через туннель выдаётся за «открыто» |
| H-5 | Скрытая зависимость | Нужна новая сторонняя библиотека, недокументированное поведение RouterOS или ключ/профиль подписи, которого нет у исполнителя |
| H-6 | Неоднозначное требование | Два прочтения issue дают материально разные продукты |

## Процедура

1. **СТОП** — прекратить текущую работу. Не «сначала дописать файл».
2. **ЗАФИКСИРОВАТЬ** — комментарий к issue в GitLab, а если проблема шире
   текущей задачи — новый issue.
3. **ПОДУМАТЬ** — предложить хотя бы два-три конкретных варианта с ценой каждого.
4. **РЕШИТЬ** — записать выбранный вариант и того, кто его выбрал.
5. **ПРОДОЛЖИТЬ** — работать по исправленному плану.

## Жёсткие правила

При H-6, когда решение зависит от предпочтения maintainer'а, агент не гадает.
Он ждёт подтверждения.

При H-4 работа останавливается, даже если дифф в остальном закончен и зелёный.
Находка по безопасности не превращается в follow-up issue по умолчанию.

При H-3 остановка происходит **до** первого коммита, меняющего формат: порядок
выката сторон (роутер, инвайты, клиенты) — решение maintainer'а.

## Что HALT'ом не является

- Красная сборка, которую исполнитель может починить. Это обычная работа.
- Находка DA уровня `I` или `R`. Это `NEEDS_REVISION`.
- Отсутствующая фича, которая агенту кажется полезной. Это новый issue.
