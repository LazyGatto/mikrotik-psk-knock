# Проверка перед заявлением о готовности

> Нет проверки — нет заявления о готовности.

## Протокол

1. Сформулируйте, что именно нужно проверить.
2. Запустите проверку.
3. Прочитайте результат целиком.
4. Сопоставьте результат с утверждением, которое собираетесь сделать.
5. Только после этого пишите вывод.

## Когда применяется

- перед словом «готово»;
- перед закрытием issue в GitLab;
- перед вердиктом `APPROVED`;
- перед коммитом или сводкой к merge request.

## Гейт — это код возврата

```bash
bash scripts/verify.sh; echo GATE=$?
```

`GATE=0` — вот гейт. Не последняя строка лога, не grep по слову «error» и не
сводка исполнителя, где написано, что тесты прошли. Гейт на grep докладывает
успех всякий раз, когда отказ сформулирован не тем словом, — именно так
сломанный код доезжает до CI.

`scripts/verify.sh` докладывает **SKIP** о стадии, которую не может выполнить на
этой машине (swift-стадии вне macOS, `--docs` без `npx`). SKIP — не PASS.
Когда пропуск недопустим, запускайте `--strict`.

## Минимум для этого проекта

- `go vet` и `go build` чисто по всем пакетам, кроме `cmd/mkpk-provision-desktop`;
- `go test` зелёный; покрытие не должно падать относительно `main` —
  измеряйте (`go test -cover`), а не предполагайте;
- `swift build` в `client-macos/` чисто, при строгой конкурентности Swift 6;
- `swift run mkpk-selfcheck` зелёный — это и есть проверка Swift-рантайма,
  `swift test` в проекте нет (CLT не несёт тестового рантайма);
- при любом изменении, касающемся токена, бакетов или формата knock'а —
  золотые векторы **перегенерированы из Go-эталона** и сверены; правка
  ожидаемого значения руками не является проверкой;
- при изменении рендера RouterOS — `.rsc`, сгенерированный из тестового профиля,
  отличается от предыдущего ровно там, где ожидалось, и нигде больше.

Живой прогон против роутера (`mkpk knock`, `mkpk-provision deploy`,
`mkpk-selfcheck live`) в гейт не входит и делегированию вниз не подлежит: это
ручная проверка maintainer'а, по одной за раз.

## Числа в отчётах

Счётчики, проценты и «изменено N файлов», названные исполнителем, пересчитываются
из кода, прежде чем быть повторёнными maintainer'у.
